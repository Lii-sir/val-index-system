# 2 目标检测

## 2.1 IoU

### 指标简介

IoU（Intersection over Union，交并比）用来衡量预测框和真实框的重叠程度。简单说，就是模型框出来的区域和人工标注区域重合得有多好。

IoU 越大，说明预测框越接近真实框；IoU 越小，说明预测框偏得越多。目标检测中通常会设置一个 IoU 阈值，比如 `0.5`，当预测框和真实框的 IoU 大于等于该阈值时，可以认为这个目标被正确检测到了。

### 计算方法

IoU 的计算公式为：

$$
IoU = \frac{ Area(PredBox ∩ TargetBox) }{ Area(PredBox ∪ TargetBox) }
$$

其中：

- `PredBox` 表示预测框；
- `TargetBox` 表示真实框；
- `PredBox ∩ TargetBox` 表示两个框的交集区域；
- `PredBox ∪ TargetBox` 表示两个框的并集区域。

简单例子：

```text
预测框面积 = 100
真实框面积 = 120
两个框交集面积 = 80
两个框并集面积 = 100 + 120 - 80 = 140

IoU = 80 / 140 = 0.571
```

这个例子中，IoU 为 `0.571`。如果检测任务设置的 IoU 阈值是 `0.5`，那么这个预测框可以算作匹配成功。

### 代码使用

```python
metrics.det.iou(pred_boxes, target_boxes)
```

输入格式：

```python
pred_boxes = [
    [x1, y1, x2, y2],
]

target_boxes = [
    [x1, y1, x2, y2],
]
```

其中：

- `x1, y1` 表示框的左上角坐标；
- `x2, y2` 表示框的右下角坐标；
- 坐标单位一般为像素；
- `pred_boxes` 和 `target_boxes` 可以是一组框，也可以是单个框。

输出格式：

```python
0.571
```

使用示例：

```python
pred_boxes = [[10, 10, 20, 20]]
target_boxes = [[12, 12, 22, 22]]

iou = metrics.det.iou(pred_boxes, target_boxes)
print(iou)
```

如果输入的是多组框，建议返回 IoU 矩阵，表示每个预测框和每个真实框之间的 IoU：

```python
[
    [0.571, 0.000],
    [0.125, 0.823],
]
```

## 2.2 TP/FP/TN/FN

### 指标简介

TP、FP、TN、FN 是目标检测里最基础的统计量。它们本身不是一个单独的指标，但很多指标都要先由这四个数算出来，比如 `Precision`、`Recall`、`F1-score`。

这四个量通常会和**混淆矩阵**一起看。混淆矩阵就是把“真实情况”和“预测结果”排成一个表，方便快速判断模型是误检多、漏检多，还是两边都比较严重。

在目标检测里，一般先按 `2.1 IoU` 的匹配规则，把预测框和真实框做一对一匹配，再统计：

- **TP**：预测框与真实框一对一匹配成功，IoU 大于阈值，且类别正确；
- **FP**：预测框没有匹配到任何真实框，或匹配到了但类别错误；
- **FN**：真实框没有被任何预测框匹配到，属于漏检；
- **TN**：因为背景区域太多，而且TN具体怎么数，常常和实现方式有关。所以只需要知道上述之外的所有情况都属于TN即可。

### 计算方法

三类目标检测里，混淆矩阵通常会把类别和背景一起放进去。比如有 `A / B / C` 三个目标类别，再加一个 `Background`，可以写成：

| 真值 \ 预测 | A | B | C | Background |
| ----------- | -: | -: | -: | ---------: |
| A           | 8 | 1 | 0 |          1 |
| B           | 0 | 7 | 2 |          1 |
| C           | 1 | 0 | 9 |          0 |
| Background  | 2 | 1 | 0 |         95 |

其中：

- 对角线上的数值表示该类别被正确识别的数量；
- 真实类别被预测成别的类别，表示类别混淆；
- 真实类别被预测成 `Background`，通常算作该类别的 `FN`；
- `Background` 被预测成某个类别，通常算作该类别的 `FP`。

混淆矩阵计算流程：

1. 先固定 IoU 阈值和类别集合，比如 `A / B / C`。
2. 对每一张图，先做框匹配：预测框和真实框一对一比较，找到 IoU 最大且超过阈值的那一对。
3. 如果预测框和真实框类别一致，就在对应位置加 `1`，同时记为该类别的 `TP`。
4. 如果框匹配上了，但类别不一致，就把“真实类别行、预测类别列”那一格加  `1`。比如真实是 `A`，预测成 `B`，就记到 `A -> B`，这对 `A` 来说是 `FN`，对 `B` 来说是 `FP`。
5. 如果真实框没找到任何匹配预测框，就把“真实类别行、Background 列”加 `1`，表示漏检。
6. 如果预测框没找到任何真实框，就把“Background 行、预测类别列”加 `1`，表示误报。
7. 每个真实框和预测框都只参与一次匹配，匹配过的框不能重复计算。

例如，还是看类别 `A`：

```text
A -> A = 8   ：A 类目标被正确检出 8 次
A -> B = 1   ：A 类目标被错分成 B 1 次
A -> C = 0   ：A 类目标被错分成 C 0 次
A -> Background = 1 ：A 类目标漏检 1 次

Background -> A = 2 ：背景被误报成 A 2 次
```

这样一来，`A` 类的统计就很清楚了：

- `TP = A -> A = 8`
- `FN = A -> B + A -> C + A -> Background = 2`
- `FP = Background -> A + B -> A + C -> A = 3`
- `TN = B -> B + B -> C + B -> Background + C -> B + C -> C + C -> Background + Background -> B + Background -> C + Background -> Background`

这里的 `TN` 是站在“把 A 当正类，其它都当负类”的角度来数的，也就是 one-vs-rest 的写法。它表示所有**和 A 无关**，而且又**没有被判成 A** 的那些格子。

其他类别 `B`、`C` 也是同样的填表方式。

在检测任务里，`TP + FN` 表示真实目标总数，`TP + FP` 表示被模型判为正的目标总数。这里先把基础统计量定义清楚，后面的 `Precision`、`Recall`、`F1-score` 再单独展开。

### 代码使用

如果后续内部代码单独提供这一类统计函数，建议接口直接返回计数和混淆矩阵，例如：

```python
metrics.det.confusion_matrix(pred_boxes, target_boxes, iou_threshold=0.5)
```

返回格式建议为：

```python
{
    "tp": {"A": 8, "B": 7, "C": 9},
    "fp": {"A": 3, "B": 2, "C": 2},
    "fn": {"A": 2, "B": 3, "C": 1},
    "tn": {"A": 101, "B": 102, "C": 103},
    "matrix": [
        [8, 1, 0, 1],
        [0, 7, 2, 1],
        [1, 0, 9, 0],
        [2, 1, 0, 95],
    ],
}
```

其中 `matrix` 按“行是真实情况，列是预测结果”的方式组织，即：

- 行对应真实类别和背景；
- 列对应预测类别和背景。

如果项目里没有明确的负样本定义，`TN` 可以不返回，或者返回 `None`，但 `TP / FP / FN` 一般都要保留。

## 2.3 Precision

### 指标简介

Precision（精确率）表示“模型判成某一类的结果里，有多少是真的”。它更关注**误报少不少**。

这个值越高，说明模型一旦报出一个目标，大多数时候是靠谱的。

### 计算方法

计算公式：

$$
Precision = \frac{ TP }{ (TP + FP) }
$$

还是以 2.2 里的类别 `A` 为例：

```text
TP = 8
FP = 3

Precision = 8 / (8 + 3) = 8 / 11 ≈ 0.727
```

这个结果表示：模型凡是报成 `A` 的框里，大约有 72.7% 是对的。

### 代码使用

如果后续代码已经有了 `TP` 和 `FP`，就可以直接算：

```python
metrics.det.precision(tp=8, fp=3)
```

也可以先从混淆矩阵里取出某一类的统计量，再计算：

```python
result = metrics.det.confusion_matrix(pred_boxes, target_boxes, iou_threshold=0.5)
precision = metrics.det.precision(tp=result["tp"]["A"], fp=result["fp"]["A"])
```

## 2.4 Recall

### 指标简介

Recall（召回率）表示“真实存在的目标里，有多少被模型找出来了”。它更关注**漏检少不少**。

这个值越高，说明模型越不容易漏掉真实目标。

### 计算方法

计算公式：

```text
Recall = TP / (TP + FN)
```

还是以 2.2 里的类别 `A` 为例：

```text
TP = 8
FN = 2

Recall = 8 / (8 + 2) = 8 / 10 = 0.8
```

这个结果表示：真实的 `A` 类目标里，有 80% 被模型找出来了。

### 代码使用

如果后续代码已经有了 `TP` 和 `FN`，就可以直接算：

```python
metrics.det.recall(tp=8, fn=2)
```

也可以先从混淆矩阵里取出某一类的统计量，再计算：

```python
result = metrics.det.confusion_matrix(pred_boxes, target_boxes, iou_threshold=0.5)
recall = metrics.det.recall(tp=result["tp"]["A"], fn=result["fn"]["A"])
```

## 2.5 F1-score

### 指标简介

F1-score 是 Precision 和 Recall 的综合结果。它希望模型既不要乱报，也不要漏报。

如果一个模型 Precision 很高但 Recall 很低，或者 Recall 很高但 Precision 很低，F1-score 都不会太好。

### 计算方法

计算公式：

```text
F1 = 2 * Precision * Recall / (Precision + Recall)
```

也可以直接用 `TP / FP / FN` 写成：

```text
F1 = 2 * TP / (2 * TP + FP + FN)
```

还是以 2.2 里的类别 `A` 为例：

```text
TP = 8
FP = 3
FN = 2

F1 = 2 * 8 / (2 * 8 + 3 + 2) = 16 / 21 ≈ 0.762
```

这个结果说明：`A` 类的检出质量还可以，但还有一定的误报和漏报。

### 代码使用

如果后续代码已经有了 `TP / FP / FN`，就可以直接算：

```python
metrics.det.f1_score(tp=8, fp=3, fn=2)
```

也可以先从混淆矩阵里取出某一类的统计量，再计算：

```python
result = metrics.det.confusion_matrix(pred_boxes, target_boxes, iou_threshold=0.5)
f1 = metrics.det.f1_score(
    tp=result["tp"]["A"],
    fp=result["fp"]["A"],
    fn=result["fn"]["A"],
)
```

## 2.6 AP / AP50 / AP75

### 指标简介

AP（Average Precision，平均精度）衡量的是模型把目标“排队找出来”的整体效果。它不只看某一个固定阈值，而是看不同置信度阈值下，Precision 和 Recall 怎么一起变化。

简单说，AP 更像是在看：模型把目标从“最像真的”到“比较勉强”的这一整条排序链，做得稳不稳。

AP50 和 AP75 也是 AP，只是匹配时使用的 IoU 阈值不同：

- `AP50`：IoU 阈值是 `0.5`，更偏向“有没有检出来”；
- `AP75`：IoU 阈值是 `0.75`，更偏向“框得准不准”。

### 计算方法

AP 本质上是 PR 曲线下面的面积：

$$
AP = \int_{0}^{1} P(R)\,dR
$$

工程里常用离散近似：

$$
AP \approx \sum_{i=1}^{n} (R_i - R_{i-1}) \cdot P_i
$$

其中 `P_i` 和 `R_i` 是不同置信度阈值下的 Precision 和 Recall，且 `R_0 = 0`。

如果写出 IoU 阈值，可以表示为：

$$
AP_{\tau} = AP\big|_{IoU=\tau}
$$

所以：

$$
AP50 = AP_{0.5}
$$

$$
AP75 = AP_{0.75}
$$

还是以 2.2 里的 `A` 类为例。假设按置信度从高到低取三个阈值，得到下面三个点：

$$
P_1 = 1.0,\quad R_1 = 0.3
$$

$$
P_2 = \frac{6}{7} \approx 0.857,\quad R_2 = 0.6
$$

$$
P_3 = \frac{8}{11} \approx 0.727,\quad R_3 = 0.8
$$

那么可以近似写成：

$$
AP \approx (0.3 - 0)\times 1.0 + (0.6 - 0.3)\times 0.857 + (0.8 - 0.6)\times 0.727 \approx 0.703
$$

这个例子表示，`A` 类在不同阈值下的整体检出质量大约是 `0.703`。

如果同一批预测框在 `IoU = 0.5` 时能匹配成功，但在 `IoU = 0.75` 时不够准，那么 `AP50` 会比 `AP75` 高。这通常说明模型能找到目标，但框的位置还不够精细。

### 代码使用

AP 计算时，输入里通常需要带置信度分数，因为它要按分数排序再画 PR 曲线。

```python
metrics.det.ap(predictions, targets, class_id="A", iou_threshold=0.5)
```

计算 `AP50` 和 `AP75` 时，只需要改 IoU 阈值：

```python
ap50 = metrics.det.ap(predictions, targets, class_id="A", iou_threshold=0.5)
ap75 = metrics.det.ap(predictions, targets, class_id="A", iou_threshold=0.75)
```

推荐输入格式：

```python
predictions = [
    {
        "boxes": [[x1, y1, x2, y2]],
        "scores": [0.95],
        "labels": [0],
    }
]

targets = [
    {
        "boxes": [[x1, y1, x2, y2]],
        "labels": [0],
    }
]
```

其中：

- `scores` 是预测框置信度，`AP` 必须要有；
- `labels` 表示类别；
- `class_id="A"` 表示只算某一个类别的 AP。

工程里常见的还有：

- `AP50:95`：IoU 从 `0.5` 到 `0.95` 取平均；
- `AP_small / AP_medium / AP_large`：按目标尺寸分开统计。

## 2.7 mAP

### 指标简介

mAP（mean Average Precision）就是把每个类别的 AP 再平均一下。它看的是“整体分类和检测表现稳不稳”，特别适合多类别目标检测。

### 计算方法

如果共有 `C` 个类别，那么：

$$
mAP = \frac{1}{C}\sum_{c=1}^{C} AP_c
$$

还是沿用 2.2 里的 `A / B / C` 三类。假设三类 AP 分别是：

$$
AP_A = 0.703,\quad AP_B = 0.660,\quad AP_C = 0.742
$$

那么：

$$
mAP = \frac{0.703 + 0.660 + 0.742}{3} \approx 0.702
$$

这个结果表示，三类目标整体平均下来，检测效果大约是 `0.702`。

### 代码使用

```python
metrics.det.map(predictions, targets)
```

推荐返回：

```python
{
    "map": 0.702,
    "per_class_ap": {
        "A": 0.703,
        "B": 0.660,
        "C": 0.742,
    },
}
```

如果只关心某一类，就用 `AP`；如果要看整体，就看 `mAP`。

# 3 语义分割

## 3.1 Pixel Confusion Matrix

### 指标简介

语义分割本质上是在做**像素级分类**：图里的每个像素都要被分到某个类别里。所以语义分割也可以用混淆矩阵，只不过这里统计的不是“目标框数量”，而是“像素数量”。

和目标检测不同，语义分割不需要做框匹配。它通常是把预测分割图和真实标注图逐像素对齐，然后统计每个像素预测对了还是错了。

### 计算方法

假设语义分割任务里有 `A / B / C` 三个前景类别，再加一个 `Background`。像素级混淆矩阵可以写成：

| 真值 \ 预测 |  A |  B |  C | Background |
| ----------- | -: | -: | -: | ---------: |
| A           | 80 | 10 |  0 |         10 |
| B           |  5 | 70 | 15 |         10 |
| C           |  0 | 10 | 85 |          5 |
| Background  |  8 |  7 |  5 |        695 |

其中：

- 行表示真实像素类别；
- 列表示预测像素类别；
- 对角线表示预测正确的像素数量；
- 非对角线表示像素被分错到了别的类别。

以类别 `A` 为例：

- `TP = A -> A = 80`
- `FN = A -> B + A -> C + A -> Background = 20`
- `FP = B -> A + C -> A + Background -> A = 13`
- `TN = 除 A 相关行列之外的其它像素数量 = 902`

这里的 `TP / FP / FN / TN` 是站在“把 A 当正类，其它都当负类”的角度来统计，也就是 one-vs-rest。

### 代码使用

建议接口直接接收预测掩码和真实掩码：

```python
metrics.seg.semantic.confusion_matrix(pred_mask, target_mask, num_classes=4)
```

输入格式：

```python
pred_mask = [
    [0, 0, 1],
    [0, 2, 3],
]

target_mask = [
    [0, 1, 1],
    [0, 2, 3],
]
```

其中：

- `pred_mask` 表示预测分割图；
- `target_mask` 表示真实标注图；
- 每个像素的数值表示类别编号；
- `num_classes` 表示类别数量；
- `ignore_index` 可以用于忽略不参与计算的像素。

推荐返回：

```python
{
    "matrix": [
        [80, 10, 0, 10],
        [5, 70, 15, 10],
        [0, 10, 85, 5],
        [8, 7, 5, 695],
    ],
    "labels": ["A", "B", "C", "Background"],
}
```

## 3.2 Pixel Accuracy

### 指标简介

Pixel Accuracy（像素准确率）表示所有像素里，有多少像素被分对了。它是语义分割里最直观的指标。

这个值越高，说明整体像素分类越准确。但它容易被大面积类别影响，比如背景很多时，即使前景分得不好，Pixel Accuracy 也可能看起来不错。

### 计算方法

计算公式：

$$
PixelAccuracy = \frac{CorrectPixels}{TotalPixels}
$$

基于 3.1 的混淆矩阵：

$$
CorrectPixels = 80 + 70 + 85 + 695 = 930
$$

$$
TotalPixels = 1015
$$

所以：

$$
PixelAccuracy = \frac{930}{1015} \approx 0.916
$$

这个结果表示：整张图或整个数据集中，大约 91.6% 的像素被分对了。

### 代码使用

```python
metrics.seg.semantic.pixel_accuracy(pred_mask, target_mask)
```

使用示例：

```python
acc = metrics.seg.semantic.pixel_accuracy(
    pred_mask=pred_mask,
    target_mask=target_mask,
    ignore_index=255,
)
```

输出示例：

```python
0.916
```

## 3.3 IoU / mIoU

### 指标简介

IoU（Intersection over Union，交并比）在语义分割里用来衡量某一类的预测区域和真实区域重合得好不好。

mIoU（mean IoU）就是把每个类别的 IoU 再平均一下。工程上通常更关注 mIoU，因为它能反映多个类别的整体分割质量。

### 计算方法

单个类别的 IoU 公式为：

$$
IoU = \frac{TP}{TP + FP + FN}
$$

以 3.1 里的类别 `A` 为例：

$$
TP = 80,\quad FP = 13,\quad FN = 20
$$

$$
IoU_A = \frac{80}{80 + 13 + 20} = \frac{80}{113} \approx 0.708
$$

如果四个类别的 IoU 分别是：

$$
IoU_A = 0.708,\quad IoU_B = 0.551,\quad IoU_C = 0.708,\quad IoU_{Background} = 0.939
$$

那么：

$$
mIoU = \frac{0.708 + 0.551 + 0.708 + 0.939}{4} \approx 0.727
$$

这个结果表示：四个类别平均下来，分割区域的重合质量大约是 `0.727`。

### 代码使用

计算单类别 IoU：

```python
metrics.seg.semantic.iou(pred_mask, target_mask, class_id=0)
```

计算 mIoU：

```python
metrics.seg.semantic.miou(pred_mask, target_mask, num_classes=4)
```

推荐返回：

```python
{
    "miou": 0.727,
    "per_class_iou": {
        "A": 0.708,
        "B": 0.551,
        "C": 0.708,
        "Background": 0.939,
    },
}
```

如果某个类别在预测和标注中都不存在，建议返回 `NaN` 或在计算 mIoU 时忽略该类别，具体规则需要在代码里统一。

## 3.4 Dice

### 指标简介

Dice 用来衡量预测区域和真实区域的重叠程度，和 IoU 很像。它在医学图像、缺陷分割、小目标分割里比较常见。

Dice 越高，说明预测区域和真实区域越接近。相比 IoU，Dice 对前景区域的重叠更敏感一些。

### 计算方法

计算公式：

$$
Dice = \frac{2 \times TP}{2 \times TP + FP + FN}
$$

以 3.1 里的类别 `A` 为例：

$$
TP = 80,\quad FP = 13,\quad FN = 20
$$

$$
Dice_A = \frac{2 \times 80}{2 \times 80 + 13 + 20} = \frac{160}{193} \approx 0.829
$$

这个结果表示：`A` 类预测区域和真实区域的重叠程度大约是 `0.829`。

### 代码使用

```python
metrics.seg.semantic.dice(pred_mask, target_mask, class_id=0)
```

如果要返回所有类别：

```python
metrics.seg.semantic.mean_dice(pred_mask, target_mask, num_classes=4)
```

推荐返回：

```python
{
    "mean_dice": 0.834,
    "per_class_dice": {
        "A": 0.829,
        "B": 0.711,
        "C": 0.829,
        "Background": 0.969,
    },
}
```

## 3.5 Precision / Recall / F1-score

### 指标简介

语义分割里的 Precision、Recall、F1-score 和 2.3、2.4、2.5 的定义一致，只是统计对象从“目标框”变成了“像素”。

- Precision 更关注某类像素有没有被多分出来；
- Recall 更关注真实属于某类的像素有没有被找全；
- F1-score 综合看 Precision 和 Recall。

### 计算方法

公式与 2.3、2.4、2.5 相同：

$$
Precision = \frac{TP}{TP + FP}
$$

$$
Recall = \frac{TP}{TP + FN}
$$

$$
F1 = \frac{2 \times TP}{2 \times TP + FP + FN}
$$

以 3.1 里的类别 `A` 为例：

$$
TP = 80,\quad FP = 13,\quad FN = 20
$$

$$
Precision_A = \frac{80}{80 + 13} \approx 0.860
$$

$$
Recall_A = \frac{80}{80 + 20} = 0.800
$$

$$
F1_A = \frac{2 \times 80}{2 \times 80 + 13 + 20} \approx 0.829
$$

### 代码使用

```python
metrics.seg.semantic.precision(pred_mask, target_mask, class_id=0)
metrics.seg.semantic.recall(pred_mask, target_mask, class_id=0)
metrics.seg.semantic.f1_score(pred_mask, target_mask, class_id=0)
```

如果已经从混淆矩阵里拿到了 `TP / FP / FN`，也可以直接传统计量：

```python
metrics.seg.semantic.precision(tp=80, fp=13)
metrics.seg.semantic.recall(tp=80, fn=20)
metrics.seg.semantic.f1_score(tp=80, fp=13, fn=20)
```

## 3.6 Boundary IoU

### 指标简介

Boundary IoU 用来评价分割边界准不准。普通 IoU 更关注整体区域重叠，Boundary IoU 更关注边缘位置。

如果模型大体分对了区域，但边界毛糙、偏移明显，普通 IoU 可能还可以，但 Boundary IoU 会下降。

### 计算方法

计算时通常先从预测掩码和真实掩码中提取边界区域，再计算边界区域的 IoU：

$$
BoundaryIoU = \frac{Area(PredBoundary \cap TargetBoundary)}{Area(PredBoundary \cup TargetBoundary)}
$$

简单例子：

$$
Area(PredBoundary \cap TargetBoundary) = 40
$$

$$
Area(PredBoundary \cup TargetBoundary) = 60
$$

$$
BoundaryIoU = \frac{40}{60} \approx 0.667
$$

这个结果表示：预测边界和真实边界的重合程度大约是 `0.667`。

### 代码使用

```python
metrics.seg.semantic.boundary_iou(pred_mask, target_mask, class_id=0)
```

常用参数：

```python
metrics.seg.semantic.boundary_iou(
    pred_mask=pred_mask,
    target_mask=target_mask,
    class_id=0,
    boundary_width=2,
)
```

其中 `boundary_width` 表示提取边界时使用的宽度。这个参数会影响结果，需要在同一项目里固定下来。

## 3.7 Frequency Weighted IoU

### 指标简介

Frequency Weighted IoU（频率加权 IoU）会按照每个类别的像素数量给 IoU 加权。像素多的类别权重大，像素少的类别权重小。

它适合看整体分割质量，但不适合单独评价小类别。因为小目标或少数类的影响会被压低。

### 计算方法

计算公式：

$$
FWIoU = \sum_{c=1}^{C} \frac{N_c}{N} \times IoU_c
$$

其中：

- `N_c` 表示第 `c` 类真实像素数量；
- `N` 表示总像素数量；
- `IoU_c` 表示第 `c` 类 IoU。

还是使用 3.1 的例子。真实像素数量分别为：

$$
N_A = 100,\quad N_B = 100,\quad N_C = 100,\quad N_{Background} = 715
$$

总像素数：

$$
N = 1015
$$

如果各类 IoU 为：

$$
IoU_A = 0.708,\quad IoU_B = 0.551,\quad IoU_C = 0.708,\quad IoU_{Background} = 0.939
$$

则：

$$
FWIoU \approx \frac{100}{1015}\times0.708 + \frac{100}{1015}\times0.551 + \frac{100}{1015}\times0.708 + \frac{715}{1015}\times0.939 \approx 0.855
$$

这个结果偏高，是因为背景像素占比很大，且背景分得比较好。

### 代码使用

```python
metrics.seg.semantic.frequency_weighted_iou(pred_mask, target_mask, num_classes=4)
```

推荐返回：

```python
{
    "fwiou": 0.855,
    "class_frequency": {
        "A": 0.099,
        "B": 0.099,
        "C": 0.099,
        "Background": 0.704,
    },
}
```
