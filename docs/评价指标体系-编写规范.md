# 评价指标体系编写规范

## 1. 总体原则

1. 按**任务类型**组织内容，再细分到具体指标。
2. 文档写法要**简洁明了**，可以口语化，但专业术语必须准确。
3. 同类指标在不同任务中重复出现时，直接引用对应章节，写法统一为：`见 3.x.x`。
4. 代码部分只做**指标计算**，不承担数据集评估、模型推理或结果汇总。
5. 除专业用语外，尽量使用中文。比如代码注释。
6. ==文档编写使用markdown。模板和整合（李晓栋），内容填充（李晓栋、颜子博），审核讨论（王英杰）==

---

## 2. 文档结构标准

### 2.1 章节组织

建议按下面顺序编写：

```text
1. 图像分类
2. 目标检测
3. 语义分割
4. 实例分割
5. 其他任务
```

每个任务下再列出具体指标。（尽量站在工业界的角度来罗列，比如工业界有些不是很在意单个类别的指标，更在乎整体的误检/漏检）

### 2.2 单个指标的固定写法

每个指标写 3 个内容：

#### 1) 指标简介

说明这个指标衡量什么，数值变大或变小代表什么。

#### 2) 计算方法

给出公式，解释主要变量，并补一个简单例子。

#### 3) 代码使用

说明输入、输出和调用示例，尽量贴近内部接口。

### 2.3 重复指标的写法

如果不同任务里有相同或近似指标，正文只保留一次完整说明，其余位置写：

> IoU 的定义和计算方法见 2.1.x，本节仅说明其在语义分割中的用法。

不要重复铺开写，避免文档变长。

## 3. 单指标内容要求

### 3.1 指标简介

写清楚三件事：

1. 这个指标衡量什么；
2. 什么样的结果算好；
3. 它适合哪些任务。

示例：

> IoU 衡量预测区域和真实区域的重叠程度，越大越好，常用于检测和分割。

### 3.2 计算方法

要求包含：

1. 公式；
2. 变量解释；
3. 一个最小计算示例。

写法尽量短，不展开过多推导。

### 3.3 代码使用

要求包含：（后面会写一套内部使用的代码）

1. 输入格式；
2. 输出格式；
3. 函数调用示例。

示例可以简短，重点是让读者知道怎么传参、怎么拿结果。

---

## 4. 代码编写标准

### 4.1 按任务类型分模块

推荐采用这种方式：

```python
metrics.det.map(pred_boxes, target_boxes)
metrics.cls.accuracy(preds, targets)
metrics.seg.semantic.miou(pred_masks, target_masks)
metrics.seg.instance.mask_ap(pred_masks, target_masks)
```

### 4.2 同一任务内统一输入输出

同一种任务类型下，所有指标尽量统一输入格式。

例如检测类指标都统一接收：

```python
pred_boxes
target_boxes
```

分割类指标都统一接收：

```python
pred_masks
target_masks
```

### 4.3 命名规则

1. 模块名按任务分层：`cls`、`det`、`seg`。
2. 指标名尽量使用业内通用缩写：`iou`、`ap`、`map`、`miou`。
3. 实例分割必须显式带 `mask`，避免和检测混淆。

建议命名示例：

```python
metrics.det.map(...)
metrics.det.ap(...)
metrics.seg.semantic.miou(...)
metrics.seg.instance.mask_map(...)
```

### 4.4 返回值规则

1. 简单指标直接返回数值。
2. 复杂指标返回字典或结果对象，保留细节信息。
3. 输入不合法时直接报错，不要静默修正。

---

## 5. 文档 编写规范

1. 章节标题层级清晰，一级标题写大类，二级标题写指标，三级标题写小节。
2. 公式用标准 LaTeX 写法。
3. 代码示例必须放在代码块里。
4. 参数、字段、变量名统一。这个会出一个模板，直接照搬就行。
5. 文档风格保持短句为主，避免大段解释。
